# 2026-09-09 run2: CLI / Python クライアント

## 実装内容

- `@vertex/cli` に全 14 op を追加した。単発 CLI とメールボックスは同じ CommandDispatcher を使い、共通の応答 JSON を返す。単発はブラウザを開いて応答後に終了し、serve は要求を継続監視する。
- BrowserSession は Chromium、ページ、ログ購読、静止待ちの寿命を所有する。core のビルド済み IIFE を `page.addInitScript({ path })` で注入し、popup の初期スクリプトにも間に合うよう context にも同じ init script を設定する。
- desktop は 1280×800、mobile は `devices['iPhone 13']`。viewport 切り替えはブラウザ/context を再作成し、UA・タッチ・isMobile・deviceScaleFactor も切り替える。popup を開くと操作対象をそちらへ移し、閉じると残ったページへ戻る。
- 全行動語彙を実装した。要素の取得は core の resolve → ElementHandle。locator による DOM 走査はない。準備待ちは存在・可視・中心の遮蔽・enabled を確認する。
- 静止待ちは MutationObserver、document.getAnimations、Playwright の request/requestfinished/requestfailed を追跡する。リダイレクトで Document が失われた場合は残り時間で測り直す。待機の既定値は WaitDefaults に集約した。
- 全 expect kind と state の全比較演算子を実装した。noException は操作前後の pageerror / console.error 累積件数で判定し、requestfailed は logs に残す。
- PNG の輝度標準偏差は screenshot の実画素から計算する。Node のバッファをブラウザ内で Blob → ImageBitmap → DOM に追加しない canvas に描画し、getImageData を読む。画像 URL を使わず img-src CSP の影響を避け、ImageBitmap を close する。追加の PNG 依存はない。
- pageerror 時に forensics/<識別子>/capture.png・observation.txt・exception.txt を保存する。ページ消滅等で一部の保存が失敗した場合は save-errors.txt を残す。
- scenario.run は viewport・stopOnFail・各手の expect / capture / audit / settleMilliseconds / comment を受け取り、result.json、PNG、監査 JSON を保存する。scenario.status は操作キューを待たず実行中にも返せる。上限到達時はブラウザを終了して未完了操作を中断し、結果保存後に応答する。
- session.begin から session.end の各手を actions.jsonl へ追記し、session.json に開始 URL・viewport・状態を保存する。export は開始 URL への navigate を先頭に追加し、expect 未達の手に指定のコメントを付ける。終了後も最後のセッションを export できる。
- MailboxServer は fs.watch + 100ms ポーリング、要求の重複受付防止、要求 JSON の検証、応答の一時ファイル → rename、要求の削除を実装した。watch の同期・非同期エラー時もポーリングを継続する。
- tools/vertex_client.py は標準ライブラリのみ。メールボックス指定・環境変数・親探索・初回作成、マーカー、要求の原子的公開、応答の削除、JSON stdout、タイムアウト・非有限値の検証を実装した。
- getting-started と README を実際の導入・起動・AI からの利用手順に更新した。

## 設計書で未指定だった点・実装上の判断

- 単発 CLI の初期 URL は `--url` → `VERTEX_URL` → `about:blank`。`--viewport` / `--headed` も受け取る。複数呼び出しでのページ・記録保持は serve を使う。
- `act.steps` はフラットな手と `action` を包んだ手を受け付ける。最初の操作失敗または expect 未達で打ち切る。共通の expect・待機値は各手の既定として継承し、手側の値を優先する。
- `scrollTo` は画面外の要素を操作可能にする行動なので、scrollIntoView 後に可視・遮蔽・enabled を確認する。その他の要素操作は準備完了前に入力しない。座標操作、navigate、back、reason に要素の準備判定はない。
- `pointer:true` + x/y、`hover:{x,y}`、drag/swipe の from/to に要素名または `{x,y}` を受け取る。swipe の to は up/down/left/right も使える。移動時間の既定は 300ms。swipe は Chromium CDP の実タッチイベントで、mobile のみ対応する。
- set は native checkbox / radio、ARIA checkbox / radio / switch、native range に対応する。radio を false にする手と range の値変更は native setter + input/change イベント、その他は Playwright のチェック操作またはクリックを使う。
- 静止待ち上限は `settled:false` とし、操作・expect が成功していれば `ok:true`。シナリオでは静止待ち上限一件と audit の各指摘を warningCount に加える。監査を失敗にするには auditClean を指定する。通信は Playwright のリクエストの開始から終了までを対象にする。
- PNG の width / height は CSS viewport ではなく実画素寸法。mobile では端末の画素倍率を含む。blank の閾値は設計どおり輝度標準偏差 3.0 未満。
- シナリオの timeoutMilliseconds はブラウザ再作成を含む実行に適用する。タイムアウト後は session.begin で再開する。異常終了後の成果物書き込み自体はタイムアウトの対象外。
- capture 名は英数字・_・-。シナリオ名は日本語も許可し、空文字・パス区切り・.・.. を拒否する。明示 directory / outputDirectory とメールボックスはサーバーの作業ディレクトリ基準で絶対パスに解決する。
- Python の既定待機は 60 秒。要求の処理を止めたとは断定できないため、タイムアウト時は req を残す。成功・失敗応答を読み終えたら res を削除する。
- stdout は text を含む一つの JSON。Testify の JSON メタ情報 + 本文の二部構成にはしていない。

## core API の確認と制約

- packages/core と packages/react のソースは変更していない。ビルドで生成する core/dist/vertex-inject.js は既存の ignore 対象。
- run1 記録には label 解決が祖先に一致する記述が残っているが、現行の TargetResolver.ts は classifyElement で観測対象へ絞り込んでいる。CLI は現行の resolve をそのまま利用する。
- VertexGlobal に raw state の取得 API がないため、state 条件は observe の state 節からキーと値を読む。eq/ne は整形済み文字列、contains は部分一致、大小比較は有限数へ変換する。文字列の改行は core と同じ表記へエスケープする。元の型の識別や構造比較はできない。
- observe は履歴を更新する API のみ。changed は操作後の core の diff を使うため、操作中の forensics 観測が差分の比較基準に影響する場合がある。
